# OppoDesk

Baseline 0.8; development branch develop/v0.9. Target: external desktop on OPPO Find X9 Ultra / ColorOS 17 without root. Java 17, Shizuku 13.1.5. Preserve main and original ZIP. Next: diagnostics, display launch API, session cleanup, DPI restoration, input tests. Firmware freeform support and physical device behavior remain unverified. Public debug key is not suitable for release signing.

## 0.9-dev12

Диагностическая сборка от dev11 для OPPO Find X9 Ultra с ColorOS 17. Отказ свободных окон в dev2 и отказ запуска из службы с указанием дисплея в dev6 относятся к испытанной прошивке. Отчёт dev10 содержит задачи Галереи и OppoDesk на внешнем дисплее. Выдержка с ограниченным числом строк оставляет расположение задачи Chrome неизвестным.

В исходниках AOSP `am display move-stack` принимает ID корневой задачи, а текущая реализация OppoDesk передаёт ID из строки `taskId=`. На OPPO надо сопоставить оба ID и дисплей в снимках до и после команды. Справка `am help` может опускать команду `am task focus`, даже если система её принимает. [ActivityManagerShellCommand.java](https://github.com/aosp-mirror/platform_frameworks_base/blob/master/services/core/java/com/android/server/am/ActivityManagerShellCommand.java)

### Проверка на OPPO

1. Подключите монитор и проверьте рабочий стол, курсор и панель задач. На телефоне откройте «Диагностика ColorOS и монитора», включите «Начать запись сценария» и вернитесь к тачпаду. Проверьте версию `0.9-dev12 (20)` в заголовке отчёта.
2. Откройте Chrome значком на рабочем столе. Подождите 3 секунды, чтобы сохранить исходный снимок. Откройте и закройте «Пуск» на мониторе без выбора приложения, затем повторите с кнопкой на телефоне. Ждите 3 секунды между действиями и отмечайте, на каком экране виден Chrome.
3. Откройте Telegram через «Пуск». Через 3 секунды отметьте, на каком экране он появился. Попробуйте переключить Chrome и Telegram через панель задач. При нормальной работе сделайте пять переключений. При исчезновении окна или появлении приложения на телефоне запишите действие, после которого это произошло.
4. Откройте диагностику на телефоне, остановите запись и скопируйте отчёт. До копирования оставьте монитор подключённым и OppoDesk запущенным. Снимки содержат пакеты, компоненты и состояние задач.
5. Повторите сценарий с Галереей в новой записи. Проверьте размеры значков 40, 64 и 96 dp, подписи и прокрутку панели задач, отсутствие перезапуска приложения при попытке фокуса отсутствующей задачи и работу после повторного подключения монитора с новым ID.

## 0.9-dev13

На CPH2841 в отчёте dev12 запуск Telegram из «Пуска» дал видимую fullscreen-задачу 2767 на внешнем дисплее 326. Оба ID задачи совпали. Задача рабочего стола 2763 осталась на мониторе скрытой и примерно через 11,5 секунды получила onResume. На снимке телефона одновременно видны Telegram и нижняя часть OppoDesk. Расположение окна во время этого снимка остаётся открытым вопросом.

Для повторной проверки включите запись сценария, запустите Telegram из «Пуска» на мониторе и оставьте оба экрана без касаний на 20 секунд. Затем остановите запись и скопируйте отчёт. В блоках «Расположение» указаны пакет, ID дисплея задачи и поля окон из WindowManager. Время команды позволяет сопоставить результат с возвратом фокуса рабочего стола. Значение «нет совпадающих распознанных строк» также возможно при отличиях формата вывода прошивки.

## 0.9-dev14

На ColorOS 17 задача Telegram 2780 и видимое окно числились на дисплее 327 от первого снимка до 16-й секунды. В этот же период пользователь видел Telegram на телефоне поверх OppoDesk. На 22-й секунде рабочий стол возобновился, задача Telegram оставалась на дисплее 327 с `visible=false`. Запись WindowManager ещё показывала видимую поверхность. На 24-й секунде оба фильтра перестали находить Telegram. Причина расхождения экранов и момент закрытия задачи требуют дополнительных данных.

Dev14 записывает тип устройства и стек слоёв дисплеев, а также историю завершений процесса после остановки записи. Для переноса проверяет принадлежность задачи пакету, переносит самостоятельную корневую задачу с телефона и подтверждает её присутствие на мониторе повторным чтением. Ярлык панели задач по-прежнему фокусирует только уже существующую задачу на выбранном дисплее.

## 0.9-dev15

В dev14 Telegram был виден на телефоне, а монитор оставался пустым. Задача 2792 была перенесена с дисплея 0 на 328, и до 24-й секунды окно числилось видимым на 328. В отчёте дисплеи отнесены к разным локальным устройствам с отдельными стеками слоёв. В истории процессов нет завершения Telegram во время этого запуска.

Кнопка «Запись с пробным запуском значком» запускает отдельный диагностический сценарий. В нём нажатие на значок в сетке рабочего стола открывает активность обычным вызовом `startActivity(Intent)` из `DesktopActivity` монитора. AOSP при таком запуске может выбрать область дисплея исходной активности. Вызов проходит без `ActivityOptions.setLaunchDisplayId` и последующего переноса задачи. Для сравнения запуск через «Пуск» использует прежний маршрут. [TaskLaunchParamsModifier.java](https://github.com/aosp-mirror/platform_frameworks_base/blob/master/services/core/java/com/android/server/wm/TaskLaunchParamsModifier.java)

Для проверки включите пробную запись, вернитесь к тачпаду, откройте Telegram значком в сетке рабочего стола и отметьте изображение на обоих экранах. Подождите 25 секунд, остановите запись и скопируйте отчёт.

## 0.9-dev16

Пробный запуск dev15 из `DesktopActivity` дисплея 329 создал задачу Telegram 2803 на дисплее 0. Первый снимок WindowManager и наблюдение пользователя подтвердили полноэкранный Telegram на телефоне. Монитор оставался пустым. В dev14 OppoDesk начал перенос задачи примерно через 57 мс после выбора ярлыка в «Пуске». Проверка права на указание дисплея в AOSP выполняется независимо от режима окна. [SafeActivityOptions.java](https://github.com/aosp-mirror/platform_frameworks_base/blob/master/services/core/java/com/android/server/wm/SafeActivityOptions.java)

Пробная запись dev16 активирует запуск из «Пуска» через `am start -W`. Перед переносом OppoDesk дополнительно ищет видимую поверхность окна активности выбранного пакета. Если снимок её не подтверждает, запись показывает причину пропуска. После переноса сохраняется проверка ID задачи из dev14.

Включите «Запись с переносом после появления окна» и выберите Telegram в «Пуске» на мониторе. Оставьте экраны без касаний на 25 секунд. В отчёте сопоставьте «Окно перед переносом», `Verified taskId` и первое состояние Telegram после переноса с изображением на обоих экранах.

## 0.9-dev17

В dev16 Android вернул существующую задачу Telegram 2803 на передний план телефона. До переноса WindowManager подтвердил видимое окно на дисплее 0. После команды та же задача и её окно числились на внешнем дисплее 330 как минимум до 24-й секунды. На скриншоте телефона Telegram по-прежнему занимает верхнюю часть экрана поверх OppoDesk. Ожидание видимого окна перед переносом в этом запуске не устранило симптом.

Dev17 добавляет снимки `dumpsys SurfaceFlinger --comp-displays` на 2-й и 6-й секундах записи после выбора приложения. Сохраняются стеки слоёв, размеры выходов и геометрия слоёв выбранного приложения и OppoDesk. Снимок позволяет сравнить решение композитора с физическим изображением. [SurfaceFlinger.cpp](https://github.com/LineageOS/android_frameworks_native/blob/lineage-23.0/services/surfaceflinger/SurfaceFlinger.cpp)

Для короткой проверки начните обычную запись, откройте Telegram через «Пуск» на мониторе и подождите 8 секунд. Скопируйте блоки «Композиция SurfaceFlinger» и отметьте, на каком экране виден Telegram.

На прошивке CPH2841_17.0.1.201(EX01) при обычном запуске Telegram через «Пуск» задача 3192 перешла с дисплея 0 на 91. Через 2 и 6 секунд WindowManager относил видимое окно к 91, а SurfaceFlinger включал слой Telegram в кадр встроенного дисплея с границами [0 0 1440 1080]. На внешнем физическом выходе 1920×1080 фильтр в обоих снимках не показал слоя Telegram. Геометрия внутреннего кадра совпадает с верхней областью телефона на скриншоте.

Для сравнения на этой же прошивке и сборке запустите Chrome через «Пуск» монитора во время обычной записи. Через 8 секунд остановите запись. Сопоставьте экран, на котором появился Chrome, с его слоем в двух блоках «Композиция SurfaceFlinger».

## 0.9-dev18

В контрольном запуске dev17 после переподключения монитора OppoDesk выбрал актуальный дисплей 92. Задача Chrome 3196 и её видимое окно числились на 92. Через 2 и 6 секунд SurfaceFlinger показывал оба слоя Chrome на внутреннем физическом выходе в области 1440×1080. Пользователь видел пустой монитор. Результат воспроизводит расхождение, обнаруженное для Telegram.

В диагностике появилась «Запись с прямым запуском через LauncherApps». Выбор приложения в «Пуске» при такой записи вызывает публичный LauncherApps.startMainActivity из DesktopActivity выбранного монитора с текущим ID дисплея. Android применяет системные правила запуска. В эксперименте нет последующего переноса или повторного запуска на телефоне. Для проверки выберите Chrome и через 8 секунд сравните оба экрана с блоками «Композиция SurfaceFlinger».

## 0.9-dev19

В dev18 на прошивке CPH2841_17.0.1.201(EX01) прямой запуск Chrome через LauncherApps на дисплей 93 вызвал SecurityException через 8 мс после выбора. В снимках до 12 секунд задача и окно Chrome отсутствовали. На 2-й и 6-й секундах SurfaceFlinger показывал DesktopActivity на внешнем физическом выходе и MainActivity на внутреннем. В dev19 строка LauncherApps содержит тип исключения и сообщение Android, если система его передала. Для проверки запустите Chrome в том же режиме записи и скопируйте строку отказа.
